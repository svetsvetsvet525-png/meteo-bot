# Варианты подключения старого телефона (Норильск, российский IP)

Телефон в Норильске может работать двумя способами:

| | Что делает телефон | Где работает бот | VPS нужен? |
|---|---|---|---|
| **А** | Держит SSH-туннель-прокси для двух гео-блокированных сайтов | Финский VPS | Да |
| **Б** | Домашний ПК держит такой же туннель | Финский VPS | Да |
| **В** | **Полностью сам сервер: бот + база + опрос сайтов** | **Телефон** | **Нет (опционально — SOCKS-страховка)** |

Tor и «бесплатные российские VPN» не годятся: exit-ноды Tor почти никогда не в РФ,
а бесплатные VPN нестабильны. Свой телефон — самый надёжный российский IP.

**Важное упрощение для варианта В:** Telegram в России работает напрямую (блок
снят в 2020-м), поэтому ни VPN, ни onion для отправки сообщений не нужны.
Onion/Tor в РФ сам заблокирован. Если в будущем Telegram начнёт «заикаться»,
можно включить SOCKS-релей через тот же VPS — одна строка `TELEGRAM_PROXY`.

# Вариант В (полный сервер на телефоне) — рекомендую попробовать первым

```
телефон (Норильск, Termux)
   ├── python -m bot  → Telegram API напрямую (без VPN!)
   ├── SQLite: ~/meteo-bot/data/bot.db
   ├── sgnorilsk.ru, meteonpr.ru, t.me/... → напрямую
   └── норильск.рф, norilsk-city.ru → с российского IP (гео-блок обойдён)
```

Плюсы: нет зависимости от VPS, бот видит сайты именно из Норильска, трафик
небольшой (опрос раз в 2 мин + часовые cooldown'ы на админ-сайты).
Минусы: телефон нужно держать на зарядке; при его перезагрузке бот поднимется
сам, только если установлен Termux:Boot. Для круглосуточной работы VPS надёжнее —
поэтому вариант А остаётся «продвинутым» выбором.

## Установка (однократно, ~10 минут)

1. Установите [Termux](https://f-droid.org/packages/com.termux/) **с F-Droid**
   (версия из Play Market не подходит) и, по желанию, **Termux:Boot** оттуда же
   (для автозапуска после перезагрузки).
2. В Termux — **одна команда**:
   ```
   curl -L https://raw.githubusercontent.com/svetsvetsvet525-png/meteo-bot/main/tunnel/termux_setup_bot.sh | bash
   ```
   Скрипт поставит пакеты и зависимости, скачает код из GitHub, создаст
   автозапуск и подскажет про `.env`.
3. Создайте файл с токеном (скрипт подскажет — это единственный ручной шаг):
   ```
   nano ~/meteo-bot/.env
   ```
   Вставьте:
   ```
   BOT_TOKEN=ваш_токен_от_BotFather
   CHECK_INTERVAL=120
   ```
   Ctrl+O → Enter → Ctrl+X.
4. Перезапустите бота (или просто перезагрузите телефон — поднимется сам):
   ```
   pkill -f run_bot_termux; termux-wake-lock; nohup bash ~/meteo-bot/tunnel/run_bot_termux.sh >> ~/bot.log 2>&1 &
   ```
5. Отключите оптимизацию батареи: Настройки → Приложения → Termux → Батарея →
   «Без ограничений». Держите телефон на зарядке.

Лог: `tail -f ~/bot.log`. Обновление кода: `cd ~/meteo-bot && git pull` + шаг 4.

### Необязательная SOCKS-страховка для Telegram через VPS

Если Telegram с телефона работает хорошо — ничего этого не нужно. Если нет:

1. На VPS разрешите вход по ключу с телефона (скрипт установки сделает это сам,
   если вызван с адресом VPS):
   ```
   bash tunnel/termux_setup_bot.sh root@<адрес-vps>
   ```
2. В `~/meteo-bot/.env` добавьте:
   ```
   TELEGRAM_PROXY=socks5://127.0.0.1:1080
   ```
3. Перезапустите бота (шаг 4 выше). `run_bot_termux.sh` сам поднимет
   `ssh -N -D 1080 root@vps` с автопереподключением. Если `TELEGRAM_PROXY`
   не задан — релей не запускается вовсе.

# Вариант А: телефон только как прокси, бот на VPS

Гео-блокированные сайты (норильск.рф, norilsk-city.ru) не отвечают из-за границы.
Телефон держит SSH-туннель к VPS, бот ходит на запрещённые сайты с российского IP.

```
бот на VPS (Финляндия)
   │  RU_PROXY=http://127.0.0.1:12080
   ▼
sshd на VPS  ◄──── ssh -R 12080 ... ────  устройство в Норильске (российский IP)
                                              │  rus_proxy.py (порт 8888)
                                              ▼
                                     норильск.рф / norilsk-city.ru
```

Туннель используется ТОЛЬКО для двух гео-блокированных сайтов (белый список
в `rus_proxy.py`). Telegram и sgnorilsk.ru бот ходит напрямую.

## Установка

1. С Windows закиньте папку туннеля на VPS:
   ```
   scp -r tunnel root@<адрес-vps>:/root/norilsk-bot-tunnel
   ```
2. На VPS в `.env` бота добавьте:
   ```
   RU_PROXY=http://127.0.0.1:12080
   ```
   и перезапустите бота.
3. В Termux на телефоне:
   ```
   pkg install -y openssh
   scp root@<адрес-vps>:/root/norilsk-bot-tunnel/termux_setup.sh ~
   bash ~/termux_setup.sh root@<адрес-vps>
   ```
   (скрипт спросит пароль от VPS один раз — чтобы поставить SSH-ключ;
   дальше всё работает без пароля; лог: `tail -f ~/tunnel/agent.log`)

## Вариант Б: домашний ПК (Windows) вместо телефона

1. Убедитесь, что `ssh root@<адрес-vps> exit` проходит без вопросов.
2. Запустите (окно можно свернуть; для автозагрузки — ярлык в `shell:startup`):
   ```
   .\tunnel\start_tunnel.ps1 -VpsHost "root@<адрес-vps>"
   ```

Достаточно ОДНОГО агента — телефона или ПК.

## Проверка туннеля (вариант А/Б, на VPS)

```
ss -tlnp | grep 12080          # туннель поднят?
curl -x http://127.0.0.1:12080 -o /dev/null -w "%{http_code}\n" https://sgnorilsk.ru/pogoda/
curl -x http://127.0.0.1:12080 -o /dev/null -w "%{http_code}\n" https://xn--h1aecgfmj1g.xn--p1ai/weather/
```
`200` — туннель жив (на втором: сайт доступен из РФ); `403` — домен не в белом
списке; `502`/`000` — сайт недоступен даже с российского IP (лежит для всех).

## Безопасность

- Прокси слушает только `127.0.0.1` на устройстве и на VPS — в интернет
  не торчит.
- Белый список доменов в `rus_proxy.py` защищает от использования туннеля
  как открытого прокси.
- sshd на VPS должен разрешать forwarding (`AllowTcpForwarding yes` —
  по умолчанию включено).
- Токен бота хранится только в `.env` на устройстве, в Git не попадает.
